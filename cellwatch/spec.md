# CELLWATCH — 現行試作の実装仕様

更新日: 2026-10-18 / モック仕様 v0.3

この文書は `master/cellwatch/` のコードの挙動を記録します。別ブランチ `main` のサーバー・Decisions API連携は[技術資料](FEATURES.md)を参照してください。画面配置・操作名・数値は完成版の確定要件ではありません。企画の正本は[コンセプト](CONCEPT.md)、病院の案は[シナリオ候補](SCENARIO-HOSPITAL.md)を参照してください。

## 1. 目的と対象

個人情報漏洩という社会課題を背景に、まず面白いゲームとして遊び、その中でセキュリティインシデントの判断と対処を学ぶことを目指す。
120秒の当直で、行き来する通信を審査し、被害を止める。対象・設計意図・審査項目への対応は [作品概要](REVIEW.md) を参照。
中央の連続セル盤面で異常を観察し、左の紙の申請書で承認・拒否を判断する。
学びは判断の結果と教科書で得る。旧PATCH / PANICとは別モック・別Sitesとして維持する。

公開先: https://cellwatch-inspection.eightman.chatgpt.site/

## 2. プロジェクト構成

リポジトリ内の作業ルート: `cellwatch/`

| ファイル | 責務 |
| --- | --- |
| `dist/index.html` | 監視卓、申請書、操作ガイド、教科書、報告書 |
| `dist/style.css` | 暗い監視卓、紙の質感、レスポンシブ表示 |
| `dist/app.mjs` | UI、盤面描画、教科書・実験台の操作 |
| `dist/engine.mjs` | 当直、申請、正解条件、スコア、対処 |
| `dist/automata.mjs` | HighLifeの世代更新、複製核、脅威フィールド |
| `engine.test.mjs` | 当直と審査・対処のテスト |
| `automata.test.mjs` | 自己複製と規則のテスト |
| `ui-wiring.test.mjs` | DOMスタブによる画面の接続テスト |
| `textbook.md` | 人が読める審査・自己複製の解説 |
| `.openai/hosting.json` | 既存Sitesの識別子と静的配信設定 |

Node.jsとPython 3を使用。外部パッケージ、ビルド工程、バックエンド、認証、DBは不要。
状態はメモリ内のみで、再読み込み・リセットで失われる。

```sh
npm run dev
npm run check
npm test
```

## 3. 現行試作の画面

- 上部: 当直の残り時間、保全率、信頼、恒久修正数、当直開始・停止・教科書・ガイド・リセット。
- 左: 審査待ちキュー、紙の申請書、任意の照合チェックリスト、調査メモ。
- 中央: 一枚の96×60セル盤面。四分割カードや独立した4枚の盤面にしない。
- 右: 脅威レベル、保全率、信頼、未審査数、直近7件の履歴、対応待ち一覧。
- 下部: 調査・隔離・承認・拒否・修復。
- 720px以下: 盤面と申請書をタブ切替。対応ボタンは画面下に追従。

領域ラベルまたは盤面上の位置を選ぶと、その領域の申請を絞り込む。
位置の対応は左上=本人確認、右上=共有、左下=入口、右下=データ出口。
これは選択操作の区分であり、セルの拡大範囲を四領域に閉じ込める境界ではない。

## 4. 当直と申請

- ゲーム内時間120秒。停止・教科書・ガイド中は進行しない。
- 0秒で最初の申請、以後7秒ごとに1件、全16件。最後は105秒。
- 原則到着から14秒で自動通過。初期期限は当直終了時刻まで。
- 隔離中は当該領域の審査期限を延長する。当直終了時に残った申請は「未審査」。
- 不正通過で脅威の複製核を生成する。未審査の自動通過も同じ。
- 根本修復済みの領域では、新たな不正申請を到着時に自動拒否する。
- 一時停止中は資料を読めるが、審査・隔離・修復は実行できない。
- バックグラウンド処理の遅延を無制限に追いかけない。フレーム処理に渡す時間差は最大0.5秒。

## 5. 通過条件

正解と説明は共通のポリシー関数から算出し、ゲームと教科書で一致させる。

| 領域 | 照合する内容 | 承認 | 拒否 |
| --- | --- | --- | --- |
| 本人確認 | 本人 / 鍵の送信先 | 二つが一致 | 不一致 |
| 共有 | 持ち主 / 閲覧者 | 二つが一致 | 不一致 |
| 入口 | 送信者 / 毎秒の件数 | 毎秒20件以内 | 21件以上 |
| データ出口 | 資料の分類 / 送り先 | 公開資料、または社内宛て | 社内資料を外部へ送信 |

上記は固定のゲームルール。現実の共有権限、本人確認、通信量の設計全般を代表するものではない。

## 6. スコアと対処

保全率・信頼は100から開始し、0未満にはしない。失った値は修復でも回復しない。

| 操作・状態 | 効果 |
| --- | --- |
| 正常な通信を承認 | 緑の通過エフェクト。減点なし |
| 不正な通信を承認・自動通過 | 複製核を生成。保全率−6。大量通信のみ保全率−3・信頼−5 |
| 不正な通信を拒否 | 当該申請は種を生成しない。既存の別脅威は消えない |
| 正常な通信を拒否 | 信頼−8 |
| 継続侵入 | 4秒ごとに侵入中の申請数だけ保全率を減らす。大量通信は信頼もその件数分減らす |
| 調査 | 現在の領域の照合ルールをメモに表示。チェック欄をクリア |
| 隔離 | 8秒間、当該領域の継続被害・世代更新・審査期限を停止。信頼−4、当直中2回まで |
| 修復 | 10秒、同時に1領域。完了時に領域由来の全複製核を除去し、以後の不正申請を自動拒否 |

被害量は生存セル数ではなく、未解決の侵入申請数で計算する。
修復の領域は選択中の領域、未選択時は審査中申請の領域、両方ない場合は本人確認。

## 7. 自己複製セル

### 7.1 正常背景

Conwayのライフゲーム B3/S23。周囲8セルを数え、誕生3・生存2/3を同時更新する。
通常の通信を表す緑の背景で、見やすさのために定期的な背景シードを補充する。

### 7.2 脅威

脅威はHighLife B36/S23。死んだセルは隣接生存数3/6で誕生し、生きたセルは2/3で生存する。
生きたセルの隣接数が6の場合は死滅する。更新元の世代を変更しながら計算しない。

12セルの複製核のRLE:

```text
x = 5, y = 5, rule = B36/S23
bb3o$bobbo$o3bo$obbo$3o!
```

十分な空間で、初期12セル・核1個 → 12世代後24セル・核2個 → 36世代後48セル・核4個。
任意のタイミングでプログラムが複製を追加する演出ではなく、隣接規則だけでこの状態になること。

| 領域 | 初期配置 | 更新速度 |
| --- | --- | --- |
| 本人確認 | 複製核1個 | 6世代/秒 |
| 共有 | 同じ核を左右反転 | 6世代/秒 |
| 大量通信 | 17セル離した核2個 | 9世代/秒 |
| データ出口 | 6セル前駆体。3世代で複製核になる | 6世代/秒 |

前駆体RLEは `b3o$o$o$o!`。
4種は別々のセル規則ではなく、共通の自己複製核の向き・配置・初期位相・更新速度で区別する。

### 7.3 境界と介入

- 各不正通過申請に独立した96×60セル層を生成し、同じ盤面に重ねる。
- 盤面外は死んだセル。端から反対側へ回り込まない。
- 同じセル層内の複製核は相互作用する。異なる申請由来の層同士は干渉しない。
- 隔離はセル層の世代更新を止め、解除後はそこから再開。
- 修復はその領域由来の層をクリアし、新規の不正な種をポリシーで拒否する。
- 青い防壁は修復状態の視覚表現。CAの静物や自然な衝突だけで全攻撃を止める設計ではない。
- 当直開始前は実際のHighLifeを黄土色でプレビュー。審査待ちは種の枠だけを表示し、まだ脅威として進行させない。

## 8. 教科書と答え合わせ

ヘッダーの「教科書」と当直報告書から開く。開いている間は当直と実際の脅威を停止する。
閉じると、開く前に実行中だった場合だけ再開する。終了済み当直は再開しない。

1. 4種の審査規則・承認例・拒否例。
2. 開閉式の現在申請の正解と理由。
3. 到着済み全申請の内容、自分の判断、正解、理由、○/×。未審査・自動拒否も区別。
4. HighLifeの規則、通常Lifeとの差、4種の配置、境界条件、参考資料。
5. 48×48セルの実験台。+1世代、+12世代、リセット。世代数・生存セル数を表示。
6. 対処の効果とコストの表。

教科書の表示自体に減点はなく、審査前に答えを確認してもよい。

## 9. 結果画面

120秒で当直を終了し、保全率・信頼・恒久修正数、領域ごとの正しい審査数・不正通過・自動拒否・未審査を表示。
教科書へ進み、個別申請の答え合わせができる。再挑戦は当直・盤面・履歴をリセットする。
関連CVEへのリンクは学習用の実例で、ゲームは攻撃手順を再現しない。
