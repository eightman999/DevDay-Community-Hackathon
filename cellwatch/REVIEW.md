# CELLWATCH — 審査基準と根拠

**面白いゲームを入口に、情報を守る判断とインシデントへの対処を知る。**

個人情報漏洩を出発点に、危険を止めることと、必要な利用を守ることの葛藤を遊びにします。病院を舞台にする案では、システムが使えず診療が止まる影響を描くことを検討しています。ゲームの楽しさを優先し、最後に現実の事例へ少しつながる構成を目指します。[脆弱性11種](LEARNING-TOPICS.md)は解説の題材候補で、敵や攻略ルールの仕様ではありません。企画の正本は[コンセプト](CONCEPT.md)、病院案の採用は[未確定](SCENARIO-HOSPITAL.md)です。

[現行プロトタイプ](https://cellwatch-inspection.eightman.chatgpt.site/) · [操作デモ](DEMO.md) · [検証記録](VERIFICATION.md)

## 公式の評価基準

[DevDay Community Hackathon公式案内](https://luma.com/OpenAIDevDay2026CommunityHackathonTokyo)（2026-10-18確認）には、新機能の活用・使いやすさ・有用性・独創性の4項目が掲載されています。予選はOpenAIモデル（GPT-6.1 SolまたはDecisions APIを予定）による自動評価とされています。

実際の評価モデル、採点プロンプト、配点、GitHub文書の読み取り範囲は未確認です。「CodexがこのREADMEを読む」とは断定せず、作品の目的・動く機能・根拠を人にもモデルにも確認しやすい形で記述します。

## 現在確認できる範囲

静的試作 `master/cellwatch/` と、サーバーを持つ `main` は別の構成です。従来の固定ルール版の記録だけで、作品全体のAPI利用を判定しません。

| 状態 | 内容 | 根拠 |
| --- | --- | --- |
| 実装済み | 汎用システムを題材にした120秒・16申請・4領域の固定ルール版 | [試作仕様](spec.md)、`dist/engine.mjs` |
| 自動検証済み | 全16件の正解で保全率100・信頼100。全件拒否で保全率100・信頼36 | `review-evidence.test.mjs`、[実行記録](VERIFICATION.md) |
| 自動検証済み | 脅威がHighLifeの規則で自己複製。12世代で核2個、36世代で4個 | `automata.test.mjs`、[実行記録](VERIFICATION.md) |
| 一部操作確認済み | 公開版で開始、教科書、実験台、誤承認後の被害など | [確認範囲と制限](VERIFICATION.md)。ブラウザ完走の記録ではない |
| 構想 | 病院の業務停止、隔離の影響、予防と復旧を描くステージ | [病院案](SCENARIO-HOSPITAL.md)。採用・実装は未確定 |
| 解説の候補 | 遊んだあとに触れる脆弱性11種。ゲームとしての再現は要件にしない | [題材と一次資料](LEARNING-TOPICS.md)。振り返りへの掲載は未実装 |
| 制作中・採用予定 | Dotsでゲーム用音楽を制作し、完成曲をゲーム内BGMに採用する計画 | [制作工程の記録](FEATURES.md#dotsによる音楽制作の記録) |
| 採用方針決定 | レビュー担当としてDotsを採用し、指摘や気づきを改善につなげる | [レビューの方針](FEATURES.md#dotsによるレビュー) |

| 技術方針・接続未確認 | MCP Eventsによる状態通知、Agents APIによる相棒・演出・短いまとめなど | [技術ごとの役割と確認状態](FEATURES.md) |
| 未検証 | 面白さ、初見操作、学習効果 | [次の検証計画](READINESS.md) |

ゲームは架空の申請を扱い、現実の個人情報や通信を取得しません。赤いセルは拡大を見せる抽象表現で、現行試作の被害数値は未解決の侵入申請数から計算します。セル数を実際の被害件数と見なす設計ではありません。

## 提出資料として揃えること

- 公開版・提出文・根拠文書で、実装状態を一致させる。
- 病院案を紹介する場合、ゲーム内の架空表現と、振り返りで触れる史実・一般的な弱点を区別する。実装した挙動に合わせてデモと検証を更新する。
- 新機能の説明には、目的、呼び出し箇所、再現手順、成功記録を添える。
- 提出方法と参加条件を公式案内で確認する。[準備状況](READINESS.md)に残作業を集約する。
