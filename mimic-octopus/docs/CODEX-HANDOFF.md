# Codexでの継続開発

## この引き継ぎの目的

ここで作ったミミックオクトパスの初期実装を、GitHubとCodexで継続できるようにするための資料です。次の担当者は現行コード、アート、遊べるルールを基準に改善してください。

GitHubの作業場所は `eightman999/DevDay-Community-Hackathon` → `mimic-octopus/` です。最初にこのフォルダへ移動してください。公開URLと実際のQA記録はREADMEにあります。

既存の初版を継続して改善します。公開版とGitHubは同じ初版を保管していますが、GitHubへのpushだけでは公開版は更新されません。変更した `dist/` を静的ホスティングへデプロイするか、Sites対応環境で同じSiteへ反映します。`.openai/hosting.json` のSite IDは既存公開版のものです。

## 現在の開発範囲

| 区分 | 内容 |
| --- | --- |
| v0.1の実装対象 | スマホ1台のソロ、90秒、4色・3形態・2タップで学習する自動リズム |
| ゲームループ | 環境更新、反応猶予、スキャン、疑われ度、成功・失敗・再挑戦 |
| 表現 | オリジナルの3Dタコ、柔らかい腕、データ群、更新の波、監視ドローン |
| 操作 | タッチ、縦・横画面、一時停止、任意サウンド |
| 後続の範囲 | 共通画面とスマホの接続、複数人ルーム、通信同期、再接続 |

ゲームロジックは15テストを通過し、縦・横のUIと軽量3D表示はブラウザで確認済みです。GPUが使える物理スマホでの操作・質感・性能確認を最初の作業にしてください。WebGL 2が使えない場合は `software-renderer.js` が同じ形状をCanvas2Dで描画します。

## まず起動する

Node.js 20以降を使用します。`dist/` を配信するビルド不要のES Modules構成です。GitHubでは描画ライブラリ本体を重複保存せず、固定した依存から初回インストール時に用意します。

```sh
npm install
npm run dev
npm test
npm run check
```

ブラウザで実際の画面を開きます。静的ファイルなので、HTMLを `file://` で直接開くのではなく、開発サーバーから読み込んでください。

次に、`AGENTS.md`、`docs/GAME-DESIGN.md`、`docs/ART-DIRECTION.md`、`docs/IMPLEMENTATION-CONTRACT.md`を確認します。画像の基準は `dist/assets/concept-gameplay.svg` です。

## 変更する場所

| 目的 | 主な場所 |
| --- | --- |
| 主役・環境・ドローン・カメラ | `dist/js/scene.js` と描画用モジュール |
| 操作、画面、音、結果表示 | `dist/js/app.js`、`dist/index.html`、`dist/styles.css` |
| 難易度、時間、判定、疑われ度 | `dist/js/engine.mjs` |
| ルールの検証 | `tests/engine.test.mjs` |
| 配信と静的チェック | `scripts/`、`package.json` |

ゲームルールは描画から独立しています。描画はスナップショットを参照し、状態を変更しません。この分離を維持すると、今後の通信入力や共通画面を追加しやすくなります。

## 次の作業の順番

### 1. 見た目を磨く

タコの顔と柔らかい腕、丸・四角・カプセルへの変形、周囲のデータの群れ、更新の波、ドローンのスキャンを確認します。コンセプトのクリーム、ココア、黄、シアンの雰囲気を保ちます。

縦画面と横画面で、主役が十分大きく、見本と操作が見えるように調整します。静止画や簡単な丸い記号への置き換えで済ませないでください。

### 2. 操作と難易度を調整する

実際にプレイして、環境変化に気づくまでの時間、2タップの分かりやすさ、形の選びやすさ、疑われ度の増減を確認します。失敗時に何を直せばよいかが伝わることを重視します。

通常の更新で1〜2要素を変え、終盤に3要素が変わる緩急を保ちます。色と形を操作している間も、覚えたリズムが自動継続する仕様を維持します。

### 3. 共通画面と通信を追加する

ソロの体験が成立した後、共通画面に見せる情報と、スマホに見せる操作を分けます。1人でも2画面に分かれる段階から、接続、時計の扱い、遅延を検討します。

その後にルーム参加、複数人、再接続を追加します。端末ごとのタイマーを正解にせず、共有するゲーム時間と入力時刻の扱いを設計してください。現時点で通信が実装済みだとは扱わないでください。

## 引き継ぎ完了時に残す記録

- ブラウザ、画面サイズ、確認した状態と操作。
- スマホ実機、音、処理負荷など、まだ確認できていない項目。
- GitHub保存先と公開URLがある場合は、その実際のURL。
