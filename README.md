# CELLWATCH — WannaCry：病院を守る60秒

情報漏洩が社会問題になっている一方で、私たちにはセキュリティの知識がまだ足りない。そこで、まず夢中になれるほど楽しいゲームをつくり、遊ぶことを知識の入口にしようと考えました。**「楽しく遊んでいたら、いつの間にかセキュリティに詳しくなる」——それがCELLWATCHです。**

守る時間は**60秒**。受付・電子カルテ・検査・予約を支えるデータの出入りを照合し、病院を守るブラウザゲームです。必要なデータを届けながら、不正な通信を遮断・隔離・根本修復します。PCブラウザ向けのデジタル審査端末です。

## 楽しさを入口に、遊ぶうちに詳しくなる

最初から脆弱性の名前を暗記する必要はありません。目の前の通信を通すか止めるか、広がる脅威をどう抑えるか。短い当直の緊張感と「次はもっと守りたい」という再挑戦の面白さを入口にします。

自分の判断で病院の状態が変わり、通すべき通信を止めることにも代償があると気づく。遊んだあとに判断の理由や現実の事例を振り返ることで、情報漏洩の原因や対処への理解につなげます。**勉強するために遊ぶだけでなく、面白くて繰り返し遊ぶうちに知識が増えていくゲーム**を目指してつくっています。

## 病院ステージ

カルテの被害は可用性（閲覧不能）・機密性（漏えい）・完全性（改変）に分け、診療予約の延期も表示します。各100件はゲームの模擬母数で、種別間の重複があり、史実の被害数ではありません。根本修復は被害の拡大を止め、既存被害は回復しません。

2017年5月のWannaCryによるNHSの診療への影響を背景にした仮想演習です。WannaCryに関連付けるのはSMBの例だけで、ほかの10種類は病院を題材にした仮想例です。実ペイロードやサイト外への攻撃はありません。[英国会計検査院（NAO）の調査](https://www.nao.org.uk/reports/investigation-wannacry-cyber%20attack-and-the-nhs/)とゲームの対応は[教科書](textbook.md)で分けて説明します。

適応型の敵は、CSVの4領域・16キャラクターの通信テンプレートから、直近の審査結果と隔離・修復状況に応じて次を選びます。各候補に同じラウンドの弱点と所見を割り当てます。OpenAI Decisions APIは通信・次の投入間隔（2/3.5/5秒）・戦術（転進/陽動/集中）の組を選びます。未設定・失敗・遅延してもローカルで継続し、APIは正解や被害量を変更しません。

背景はLife（B3/S23）、脅威は実際に自己複製するHighLife（B36/S23）。既存の12/36世代の検証を維持しています。ゲーム内の模擬通信のみを扱い、実ネットワークへの攻撃機能はありません。

## ローカル実行

Node.js 22.9以降（検証: 26.8）。依存パッケージのインストール、ビルドは不要です。

```sh
npm run dev
```

[ローカル端末](http://127.0.0.1:8766/) を開きます。サーバーは127.0.0.1にだけ待ち受けます。既存のサーバーが同じポートを使用中なら停止するか、`CELLWATCH_PORT=8767 npm run dev` で別ポートを使います。

初期状態は適応型。開始前の「敵の動作」で「CSV順（練習）」も選べます。モードの変更はリセット後に行います。API未設定でもゲームと相棒の定型応答で遊べます。

## 操作と音声

「当直開始」で開始し、申請の6項目を規則と照合して「通す / 遮断」を選びます。キーボードは左矢印で遮断、右矢印で通過。「一時停止」や「教科書」で資料を確認し、先輩が領域ごとの隔離・根本修復で被害を抑えます。リセットで状態を消してやり直せます。

BGM・SEは画面上部で個別に切り替えられ、BGM音量も調整できます。音声はユーザー操作後に開始します。BGMはブラウザ内のWorkerで合成し、未解決の侵入数に応じて120〜180 BPMへ変化します。音声生成に失敗してもゲームは継続できます。音源と実装の出典は[Uzumeの記録](dist/vendor/README.md)を参照してください。

## 6項目を組み合わせる審査

技術所見2項目に、送信主体と認証主体の一致、役割と申請操作、情報区分と送信先、展開後の処理量を加えた6項目を審査します。一つでも違反・欠損があれば遮断。確認チェックはメモで、採点や正解表示ではありません。

| 確認項目 | 演習の規則 |
| --- | --- |
| 技術所見A / B | 弱点CSVのsafeA / safeBにそれぞれ一致 |
| 主体 | 送信ジョブIDと認証トークンの主体が一致 |
| 権限 | 診療担当は参照・更新、連携担当は参照・転送、閲覧担当は参照のみ |
| 情報の送信 | 公開資料は外部可。院内情報は院内のみ。診療情報は院内、または匿名化と連携承認の両方がある契約先のみ |
| 処理量 | 展開後の整数MBで受付20、電子カルテ40、検査80、予約30以下。上限ちょうどは許可 |

技術所見が正常でも、主体不一致・権限外操作・送信条件違反・容量超過で遮断になります。反対に、公開資料の外部転送や承認・匿名化のある診療情報の契約先転送は通せます。単語一つの印象ではなく、複数の値の関係を確認します。

所見の生成は決定的です。正常テンプレートは6項目を満たし、不正テンプレートは6項目のうち一つだけ違反します。固定順16件でも全6種類の違反と、条件付きで許可される申請が登場します。元CSVの正常/不正、既存の11弱点・4領域・16候補は維持します。追加証拠の生成と規則はdist/threats.mjsのmakeInspection / inspectionChecksが共有し、UI・採点・教科書・API候補説明に反映します。追加証拠が欠けた検査データは許可しません。

審査期限は到着から14秒（当直終了まで）。一時停止中にも資料を読めます。行チェックでは答えを出さず、判定後に違反項目と適用規則を調査ログ・履歴へ表示します。教科書の未審査申請の答えも隠します。スクロールできる審査表に6項目を表示し、PCの判定ボタンの位置を保ちます。これらは演習独自の規則です。

## Decisions APIを使う

1. `.env.example` を参考に、ローカルの `.env` を作成します。
2. `OPENAI_API_KEY` に自分のAPIキーを設定します。キーはサーバーだけが読みます。`dist/` やCSVに入れないでください。
3. `CELLWATCH_ENEMY_MODE=auto` のまま `npm run dev` を起動します。キーがあればDecisions、なければローカルで選択します。設定を変更したらサーバーを再起動してください。

`.env` はGitの対象外です。キーをブラウザや回答へ貼る必要はありません。

| 設定 | 意味 |
| --- | --- |
| `OPENAI_API_KEY` | 空ならローカルで動作 |
| `CELLWATCH_ENEMY_MODE=auto` | キーの有無でDecisions/ローカルを選択（既定） |
| `CELLWATCH_ENEMY_MODE=local` | キーがあってもAPIを呼ばない |
| `CELLWATCH_ENEMY_MODE=decisions` | Decisionsを優先。キーなし・失敗時はローカル |
| `COMPANION_AI_ENABLED=true` | キーがある場合にAgents APIの相棒を有効化（既定はfalse） |
| `CELLWATCH_PORT=8766` | ローカルサーバーのポート。未指定時は`PORT`も参照 |

実装では[OpenAI Decisions API](https://developers.openai.com/api/docs/guides/decisions)の`POST /v1/decisions`、`gpt-6-luna`、通信・間隔・戦術を束ねた候補から1件選ぶ`choice`を使用します。APIにはゲームのラウンド・防御状態・直近24件までの判定と、CSV候補の弱点名・同じラウンドの検査所見・影響を渡します。画面や自由入力、キーを観測データとして送りません。

初手はCSV #001をローカル選択。次の投入の4秒前に先読みし、1当直あたり最大15回（初期16件の場合）。サーバーのプロセス/Workerインスタンスごとに最大64回までです。上限到達後もローカルで続行し、再試行で課金を増やしません。実APIの利用はOpenAIの利用料金・アカウント権限に従います。

サーバーの応答期限は3.2秒、ブラウザのHTTP待ちは3.6秒、directorの期限は3.8秒。期限を過ぎた回答は出題を遅らせず破棄します。同じ当直・ラウンドへの重複呼出は共有します。APIの拒否、未知の候補、不正な確信度・確率、HTTPエラーもローカルへ切り替えます。

「確認メモ・一時隔離・根本修復」の3ボタン列は表示せず、先輩が自動で支援します。確認メモは2秒ごとに1項目、侵入が起きた領域は隔離・修復の候補にします。AIの選択を最大8ゲーム秒待ち、遅延・未設定時はローカルで対応します。実行直前に状態を再確認し、隔離2回・予約4件延期、修復10秒・同時1領域の制限を守ります。通過・遮断はプレイヤーが判断します。停止中は自動対応も止まります。行クリックの確認メモも利用できます。

## 先輩オペレーター / Agents API

自動サポートは当直ごと最大6回のAPI選択を使い、その後もローカルで続けます。相談は最大5回、終了後の振り返りは1回です。自動対応の内容と判断元は通信欄に表示します。

右列の「相棒の通信欄」から当直中に最大5回相談できます。一時停止中にも利用でき、スマートフォンでは監視マップ・通信審査の両画面からアクセスできます。相談すると定型のヒントを即表示し、AIの返信待ちでも当直は継続します。判定後・修復・被害の重要イベントには、APIを呼ばず定型の通信を表示します。

ローカルでは `COMPANION_AI_ENABLED=true` と `OPENAI_API_KEY` を設定してサーバーを再起動します。同一オリジンの `POST /api/companion/message` を通じてAgents APIへ問い合わせます。正解・採点・被害はエンジンが確定し、判定前の正解や具体的な違反項目は相棒へ送りません。AIは観察手順を案内し、当直終了後は自動で「良かった点・見直す点・次の当直で試すこと」を振り返ります。

未設定・未ログイン・APIルートなし・応答不正・接続失敗・期限超過・上限到達時は、理由を添えた定型応答へ切り替えます。返信元を画面で示し、未ログイン時はログインリンクを表示します。相談の二重送信を防ぎ、リセット・当直終了・審査対象の変更後に届いた相談の返信は破棄します。

Agentsのhosted sessionはメッセージごとに作成し、応答処理後に削除します。Sitesでは返答と削除処理をwaitUntilで保持し、画面の相談を中断しても削除を継続します。削除失敗はサーバー側で記録します。画面の直近3件の通信と当直履歴はブラウザのメモリ内に保持し、永続保存しません。サーバーの一時的な重複防止キャッシュを除き、当直を通じたhosted sessionの継続利用はしません。Agentsの呼び出しはプロセス/Workerインスタンスごとに最大32回で、複数インスタンスや再起動を横断する全体予算ではありません。

## CSVと配信

- [弱点CSV](dist/data/attack-patterns.csv): 11種類の弱点、二つの検査条件、影響・修復・公式出典と被害種別の14列。
- [領域CSV](dist/data/vulnerabilities.csv): 4領域の表示と、元テンプレートの正常/不正を選ぶポリシー設定。
- [通信CSV](dist/data/incidents.csv): 初期16件の通信テンプレート。元のA/B、補助4欄、キャラクター名・役割・発言・画像参照を管理。
- [CSV編集手順](dist/data/README.md): 列、引用符、規則トークン、検証方法。

画面と採点は共通の`inspectionVerdict`・`inspectionReason`を使います。元のA/Bは正常/不正の所見例を選ぶ正本として保持し、所見のある申請では技術所見に主体・権限・送信条件・処理量を加えた6項目で採点します。補助情報やキャラクターの見た目・発言は正解に影響しません。CSVの16候補にはGPT Imageで個別生成した画像 `dist/assets/characters/incident-01.png`〜`incident-16.png` を割り当て、生成プロンプトは `artifacts/hospital-character-prompts.json` に記録します。

適応型では同じテンプレートを繰り返し選ぶことがあり、投入順は変わります。CSV順16枠では全11種類の弱点が登場します。全領域を防御すると不正通信を避けて正常通信を選び、候補がなければその投入枠を待機します。10秒の根本修復は、その領域の複数対策をまとめたゲーム上の抽象で、実際の修正時間を再現しません。

`dist/`だけの静的配信も維持しています。APIルートのない配信先では自動的にローカル適応へ切り替わります。CSV順の練習とローカル切替は従来の3.5秒間隔です。Decisionsの転進は直前の経路を避け、集中は直近に不正通過・自動通過を許した経路を優先し、陽動は正常通信を選びます。全16枠を維持し、間隔が長い場合も最後の枠が52.5秒までに入るよう調整します。

## Sites Worker

Sites向けのWorkerアプリは`sites/`に置き、静的ゲームと同じオリジンの`/api/enemy/decide`・`/api/enemy/status`・`/api/companion/message`を配信します。ローカルサーバーとWorkerは`server/decision-service.mjs`の選択・検証・期限・予算処理を共有します。Sitesの識別子は既存の`.openai/hosting.json`を維持します。

```sh
# Sitesの依存準備後、ルートで実行（ローカルゲームには不要）
npm run build
```

`sites/`はVinext + Cloudflare Workerです。ルート`dist/`のゲームソースを保持して`dist/server`・`dist/client`・`dist/.openai`へ公開成果物を生成します。詳しい設定は[Worker手順](sites/README.md)を参照してください。

Workerの`OPENAI_API_KEY`（secret）・`ENEMY_AI_ENABLED=true`・`ENEMY_MODE=decisions`・`COMPANION_AI_ENABLED=true`は配信環境のサーバー側設定として与えます。AIモードではSitesのChatGPTログインが必要で、未ログインの場合はローカルで継続しログインリンクを表示します。静的ファイルへキーを埋め込まないでください。キー未設定ならローカル適応が動きます。インスタンス内のDecisions 64回・Agents 32回制限はアカウント全体や複数Workerを横断する課金上限ではありません。

既存の[公開ゲーム](https://cellwatch-inspection.eightman.chatgpt.site/)の識別子・公開範囲を維持してWorker版を配信します。配信状態はSitesのdeployment statusで確認してください。Agents APIの相棒を含むWorker版は公開済みです。ログイン後の相棒返答と、匿名時のローカル継続を本番で確認しています。最新配信の成否はdeployment statusと公開URL上の動作を確認してください。プレイヤー履歴の永続化は実装していません。

今回作成したキーは7日間有効です。期限後はAIが定型応答・ローカル選択へ切り替わるため、この設定だけで永続的な自動稼働にはなりません。更新時はサーバー側secretを差し替え、疎通を確認してください。
