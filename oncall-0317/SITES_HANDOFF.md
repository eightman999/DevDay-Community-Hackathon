# ChatGPT Sites / Web ホスティング引き継ぎ

このプロトタイプの公開・Site作成は**未実施**です。大会の事前公開ルールを必ず確認してください。

## Sitesで取り込む場合

`standalone-preview.html` を参照元として渡すと、OP、3局面、事後報告書が1ファイルで分かります。UIを再構成する場合は `public/` のHTML/CSS/JSと `PLAN.md` を仕様として使ってください。

```text
@Sites 添付の「standalone-preview.html」と「PLAN.md」を参照し、
「03:17 — ON CALL」という、120秒のセキュリティ教育タワーディフェンス風ゲームを構築してください。

必須：深夜の着信OP、サービス防衛マップ、3局面の判断、
対応に応じた状態遷移、学習モード、実在CVEと区別した事後報告書。
UIは操作できる状態で、PCとスマホに対応。
API未接続の自由記述は必ず「ローカル判定・AI未使用」と表示してください。
Decisions APIを本番接続する場合、APIキーをサーバー側に置き、
判定されたアクションを実行前にプレイヤーに確認させてください。
公開前に主催者の事前制作ルールを確認してください。
```

## 静的公開（デモ版）

`public/` のファイルだけでゲームは動作しますが、自由記述はローカルの簡易分類になるため、新機能を活用した**ライブAPIの証拠にはなりません**。`standalone-preview.html` も同様。

## Decisions API本番接続

`server.mjs` はローカルNodeサーバーです。Cloudflare WorkersならWorkerに、Vercelならサーバレス関数に `/api/evaluate` を移植してください。ゲームロジックの実体はブラウザ側にあります。`decision.mjs` の問い定義と応答の検証を参照できます。

- クライアント側へAPIキーを埋め込まない。
- 同一オリジンのバックエンドだけが OpenAI API にアクセス。
- API入力の最大文字数300、段階0〜2。
- 失敗、拒否、unknownを確認し、固定アクションに戻せるようにする。
- サーバー側でIP別の上限・予算上限・使用量確認を行う。
- プロダクションでは本サンプルの簡易IPレート制限だけでは不十分。

## 検証ポイント

1. 公開URLにシークレットウィンドウでログインなしでアクセスできる。
2. スマートフォンでOP→3局面→報告書を完走できる。
3. `OPENAI_API_KEY` がデプロイ済みJSやビルド成果物に含まれない。
4. ライブAPIとローカル分類の表示が違い、失敗を成功扱いしない。
5. 実在CVEのリンクが切れていない。
6. 新規・非公開プロトタイプの大会規約を主催者に確認している。
