# 03:17 — ON CALL | DevDay Community Hackathon 2026 実装計画

- 版：2026-10-18 / 非公開プロトタイプ `v0.1.0`
- 制作テーマ：13歳以上向け・120秒で学ぶ「開発すると守る場所が増える」インシデント対応タワーディフェンス風ゲーム
- 本書の位置づけ：大会ルールに基づく事前企画・非公開試作。**大会で提出してよいかは主催者の解釈を優先**する。事前に公開済みの作品をそのまま出すことは避ける。

## 1. 30秒で説明できる企画

> 午前3時17分、障害対応の電話で起こされたITエンジニア。新機能の公開後、他人の資料が見える問題が起きた。120秒の間に調査、応急処置、根本修正、安全な再リリースを判断する。最後に本物のCVEやCWEと照らした事後報告書が届く。

**プレイの核心**：「攻撃を止める」と「脆弱性を直す」は違う。攻撃ユニットを消してもサーバーの認可不足が残れば再発する。逆に、原因を直せば正規の利用を続けながら不正な閲覧経路を塞げる。

## 2. 審査4観点への対応

| 公式の観点 | 最低限達成すること | 自動審査に見せる証拠 |
|---|---|---|
| 新機能の活用 | DevDay 2026 Decisions API：自由記述を固定カテゴリへ分類 | `decision.mjs` の `/v1/decisions` 呼び出しと `README.md` の API接続ガイド、実際の通信成功時の表示（要当日検証） |
| 使いやすさ | ログイン不要、3局面、説明可能なアクション、時間制限なしの学習モード、スマホ対応 | スタート→プレイ→報告書のスクリーンショット・操作手順 |
| 有用性 | 認証/認可の違い、応急処置と根本対応、リリース前の権限テストを学ぶ | 固定の学習ノート・行動によって異なる事後報告書・CWE/CVE原資料リンク |
| 独創性 | サービスをマップに見立て、新機能で攻撃経路が増える。安全性とサービス継続のトレードオフ | マップと時間・可用性・侵害進行の状態遷移 |

一次審査は公式告知によると GPT-6.1 Sol または Decisions API による自動評価**予定**。審査を操作する文面ではなく、README の内容・コード・実際の挙動を一致させる。

## 3. ゲーム仕様：1〜3分（目標120秒）

### オープニング（10〜15秒目安）
- 03:17、着信。運用担当「本番で、他人の資料が見えているかもしれない」
- 通常モード（120秒）、学習モード（カウントダウンなし）を選ぶ。
- 導入説明を長々と表示せず、1クリックで演習開始。

### Phase 1 / 初動判断
- 観測：ログイン済みユーザーが、本来許可されていない資料に到達。
- 選択：ログ調査 / 共有機能の一時停止 / 不審な接続元の遮断。
- 学び：調査にも時間がかかる。一時停止には可用性の負担がある。接続元だけ遮断しても弱点は残る。

### Phase 2 / 原因修正
- 観測：資料IDを用いたアクセスで、資料ごとの閲覧権限確認が不足。
- 選択：サーバー側の認可確認 / UI上のリンク非表示 / レート制限。
- 学び：認証（誰か）と認可（その資料を見てよいか）の違い。UIだけ直すと再発する。

### Phase 3 / 新機能リリース
- 観測：管理者向けプレビューという新しい経路の追加を予定。
- 選択：権限テストしてから公開 / 確認を省いて公開 / リリース延期。
- 学び：開発自体が悪いわけではない。テストと公開停止の意思決定が重要。

### リザルト（時間無制限で読める）
- 派手なゲーム内表彰ではなく、**インシデント事後報告書**へ切り替える。
- 対応履歴、影響度（架空の演習値）、根本修正の有無、3つの学び。
- 実在CVE **CVE-2023-22515** の一次資料リンクと **CWE-862** を表示。
- **架空の共有サービスと実際のConfluence脆弱性は同一ではない**ことを明記する。

### スコアについて
- ゲーム内部の指標：残り時間、サービス稼働（架空値）、情報流出リスク（架空値）、攻撃進行度（架空値）、未対応の技術的負債。
- ランクは**教育演習用のゲーム評価**。実際のCVSS、侵害確率、危険度、CVE評価の代替ではない。
- 調査・修正・リリース確認の結果によって指標が変わる。API分類の信頼度が低い場合は行動を実行しない。

## 4. MVPの画面

1. **電話OP**：真夜中の自室・運用担当からの着信、開始ボタン。
2. **防衛マップ**：入口→Web→認証・共有→データ保管庫。緑の正規アクセス、赤い不審アクセス、弱点を異なる記号で示す。
3. **判断パネル**：3択と、自由記述テキスト欄。API判定結果は実行前に必ず確認。
4. **事後報告書**：判断履歴、原因、学び、参考CVE/CWE、印刷/PDF保存。

MVPでは実際のリポジトリ検査、SQLインジェクションの実行、対外スキャン、リアルな攻撃コード、複雑なパスファインディング、リアルタイムのマルチプレイは実装しない。

## 5. Decisions APIの責務

API は**プレイヤーの自然文 → 有限カテゴリ**の分類だけを担当する。モデルは `gpt-6-luna`。APIエンドポイントは `POST https://api.openai.com/v1/decisions`（ベータ仕様、イベント時点に要再確認）。

- `choice(response_category)`：調査、封じ込め、接続元遮断、サーバー側の根本修正、UIだけの変更、レート制限、テスト、急ぎ公開、延期、unknown。
- `predicate(concrete_response)`：具体的で実行可能な提案を含むか。
- 低信頼度・拒否・範囲外→`unknown`として扱い、手動選択へ誘導。
- 推定した行動は**自動実行しない**。対応候補を表示し、プレイヤーが確認した後に固定ルールで実行。
- 文章解説は検証済みの静的教材から表示。Decisions API に新しいCVEや被害事実を捏造させない。
- APIキーがない場合はキーワードによる**ローカルデモ判定（AI未使用）**を利用。明確にその表示を出す。API が失敗した場合もAI使用済みとは表示しない。
- APIキーをHTML、JavaScript、Gitリポジトリに保存しない。APIはサーバー経由。

## 6. 技術設計

```
Browser (HTML/CSS/Vanilla JS)
 ├─ state machine: intro → phase 1 → phase 2 → phase 3 → report
 ├─ simulated SVG network / animated events / action log
 ├─ deterministic game rules (no security claim)
 └─ POST /api/evaluate  (free-text only)
             |
 Node.js mini-server (Node 18+, no npm dependencies)
 ├─ no API key → offline demo classifier
 └─ OPENAI_API_KEY + ENABLE_DECISIONS_API=1
             └─ OpenAI Decisions API /v1/decisions
```

ローカル実行は `npm start`。静的試用は `standalone-preview.html` を直接開く。Vercel/Workers/Sites公開時は**サーバー側のAPIルートを各ホスティング向けに調整**する。静的ファイルだけならデモ判定のみ。

## 8. リスクと縮退戦略

| リスク | その場での対策 |
|---|---|
| API のアクセス権やトークン・料金の問題 | ローカル判定への切り替えを明示。実際のAI活用を示せない場合は審査上の弱点として正直に記載 |
| API の回答が曖昧・不正解 | `unknown` として実行せず、固定選択肢で続行 |
| 本格TDの実装に時間がかかる | SVGマップの侵入経路アニメーション＋固定選択肢を優先 |
| 文字量が多すぎる | 30秒で分かるOP、行動の説明は短く、詳細は報告書へ |
| 13歳には難しい | シンプルな日本語とツールチップ。認証と認可は実例で説明 |
| 事前試作の大会規約抵触 | プロトタイプとして非公開・未提出のまま保持し、主催者確認。公開済み成果物の再提出をしない |

## 9. MVPの受け入れ条件

- [ ] PCからOP→3局面→報告書へ到達できる。
- [ ] 120秒の時間切れでも報告書が出る。
- [ ] 学習モードでは時計が減らない。
- [ ] マップの選択によって説明が切り替わる。
- [ ] 応急処置と根本修正の結果が違う。
- [ ] UI非表示だけの対処では危険が残る。
- [ ] 新機能のテスト・拙速な公開・延期で結果が変わる。
- [ ] 自由記述の分類は確認後にのみ実行される。
- [ ] オフラインデモと本物のAPIが画面上で区別される。
- [ ] CVE-2023-22515を、ゲームの再現事例と誤認させない。
- [ ] APIキーはクライアントのファイルに存在しない。
- [ ] 少なくとも一度、会場のネットワークから公開URLを開いて動作確認する。
